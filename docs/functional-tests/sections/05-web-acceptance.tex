\section{Web 页面与全链路验收}

\subsection{当前状态}

Streamlit 已接入 FastAPI。2026-07-17 已在 Codex App 内置浏览器中使用 Playwright 完成无真实订单的视觉和交互验收；隔离 FakeExchange 环境验证了多空运行行、草稿预览与编辑、停止、归档、删除、详情切换和 Cell 数据。随后以本地 HTTP Stub 和 AppTest 补充 9 项前端异常场景。验收共确认币对链接、表格裁切、旧预览残留和异常响应崩溃四类缺陷，详见执行记录。

\CaseHeader{FT-WEB-001}{总览数据来自真实 API}{\OwnerAuto+\OwnerHuman}{无资金/视觉}{\StatusPass}

总览每行显示币对、方向、当前价格、当前网格上下限、比例、单格金额、杠杆、网格总数、待建仓、已建仓、待平仓、状态与运行时间。做多整行绿色、做空整行红色、未启动白色。人工确认无横向滚动条且少量网格完整展示。

\CaseHeader{FT-WEB-002}{新增策略与预览}{\OwnerHuman}{配置写入}{\StatusPass}

点击表格下方加号，输入做多/做空配置并生成预览。确认页面预览与 \texttt{/strategies/preview} 完全一致；确认创建后 SQLite 出现草稿，未产生订单。

\CaseHeader{FT-WEB-003}{编辑、启动与不可逆锁定}{\OwnerJoint}{可能启动实盘}{\StatusPartial}

草稿阶段编辑成功；首次启动后编辑控件禁用，停止后仍不可编辑。启动动作必须二次确认测试币对、方向、单格金额和预计最大 Cell 数。

\CaseHeader{FT-WEB-004}{停止、归档和删除}{\OwnerJoint}{状态变更}{\StatusPass}

停止单组不停止共享调度器且不撤币安订单；归档和软删除保留审计数据。页面不得暗示停止等同于平仓或撤单。

\CaseHeader{FT-WEB-005}{币对详情和实时价格行}{\OwnerHuman}{视觉}{\StatusFail}

币对下拉在标题下方左侧；多空详情整行颜色正确；运行时间使用“3小时18分”而不是时刻。实时价格行按价格插入待平仓和待建仓之间，文字为白色。

\CaseHeader{FT-WEB-006}{Cell 订单展示}{\OwnerHuman}{视觉/数据}{\StatusFail}

每格展示买入价、卖出价、当前阶段、买入、卖出和成交次数。订单文字使用“挂单:\#单号”或“成交:\#单号”；待平仓不重复显示已建仓。价格顺序必须符合多空触发逻辑。

\CaseHeader{FT-E2E-001}{浏览器到币安全链路（旧总括用例）}{\OwnerJoint}{测试网订单}{\StatusPartial}

2026-07-17 已完成后端真实单链闭环和页面显示核对，但最终策略通过隔离 API 创建、启动，不属于全程页面发起。严格的页面驱动用例与安全门禁见“页面驱动的 Binance Testnet 基本 E2E”一节。

\textbf{步骤：}
\begin{enumerate}
  \item 从 Web 创建独立测试策略并核对预览。
  \item Web 启动策略，确认 FastAPI 状态、共享调度器 PID 和币安挂单。
  \item 人工在币安页面取消一张订单，观察 Web 在一个一致性周期内更新为新订单号。
  \item 触发或用受控方式完成一次建仓/平仓闭环，核对 Cell、事件、手续费与持仓池。
  \item Web 停止并归档测试策略，人工确认是否需要撤销剩余测试单和清理仓位。
\end{enumerate}

\textbf{通过：}五层状态（浏览器、API、SQLite、调度器、币安）一致，页面刷新不依赖模拟数据，不出现重复订单或残余测试仓位。
