# 固定等 U 网格原地重配（SOL 验证）

## 对象与账本

- 策略对象保持原 `strategy_id`、首次启动时间、最初建仓价及全部历史成交记录。
- 每次重配增加 `grid_generation`。新单元格使用新 ID，预算、交易次数、格内利润和复投次数从零开始。旧单元格不再参与下单，但其不可变成交与价格记录继续用于策略级累计利润。
- 策略级纯网格净利按所有代际的已配对买卖成交累计。迁移时的调仓成交属于仓位调整，不冒充单元格网格利润；其实际手续费和已实现盈亏单独列入绩效结果。
- 已支付但尚未随旧单元格卖出结转的开仓手续费，按保留仓位比例转入新单元格的虚拟买入批次；新增买仓的实际手续费也转入该批次。后续新格卖出时一次扣除。

## 重配前提

策略必须已停止；该交易品种的全部交易所挂单必须撤销并在本地账本完成对账；实际多仓应等于旧单元格逻辑仓位；历史成交和手续费覆盖必须完整。当前原型保持策略总预算不变，按新格卖侧目标数量计算仓位差额。调仓单确认全部成交、实际仓位等于新目标后，配置、单元格和迁移事件在一个 SQLite 事务中写入。

目前原型由 `GridService.preview_fixed_reconfiguration` 与 `apply_fixed_reconfiguration` 提供，尚未开放网页重配入口。SOXL 实盘策略未使用这套原型。正式迁移还需要将调仓意图做成可恢复的持久任务，并为撤单后的迟到成交加入自动对账。

## 2026-11-17 OKX SOL 实盘小额验证

- 环境：OKX 实盘、`SOL-USDT-SWAP`、全仓 1 倍多仓。测试策略 `sol-usdt-swap-fixed-06a08dfb`，总预算始终为 400 USDT。
