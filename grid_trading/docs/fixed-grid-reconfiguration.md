# 固定等 U 网格原地重配

## 对象与账本

- 策略对象保持原 `strategy_id`、首次启动时间、最初建仓价及全部历史成交记录。
- 每次重配增加 `grid_generation`。新单元格使用新 ID，预算、交易次数、格内利润和复投次数从零开始。旧单元格不再参与下单，但其不可变成交与价格记录继续用于策略级累计利润。
- 策略级纯网格净利按所有代际的已配对买卖成交累计。迁移时的调仓成交属于仓位调整，不冒充单元格网格利润；其实际手续费和已实现盈亏单独列入绩效结果。
- 已支付但尚未随旧单元格卖出结转的开仓手续费，按保留仓位比例转入新单元格的虚拟买入批次；新增买仓的实际手续费也转入该批次。后续新格卖出时一次扣除。

## 重配前提

重配任务会停止策略并等待共享调度器退出，撤销该交易品种由旧单元格拥有的挂单，逐笔结算撤单期间的成交。其他来源的挂单、未确认的下单、仓位不符或不完整的历史成交会阻止迁移。确认实际多仓等于旧单元格逻辑仓位后，按新配置的卖侧目标仓位计算一笔调仓。调仓单确认全部成交、实际仓位等于新目标后，配置、单元格和迁移事件在一个 SQLite 事务中写入，再启动策略。

重配任务保存在 `fixed_reconfigurations` 表，任务 ID 可重复提交而不会生成第二笔调仓。调仓前先持久化计划及唯一客户订单号；请求结果不确定时只按该订单号查询，不盲目重复下单。网页策略详情提供预览、执行、继续和撤销入口。撤销只适用于尚未提交调仓且旧仓位可对账的任务。已提交但不能确认的任务需要检查成交后继续处理。

新预算可不同于旧预算。若要延续已经复投的金额，应把旧策略当前 `grid_budget_usdt` 用作新预算；新格预算会按总额均分，并按精度处理尾差。历史纯网格净利与交易次数连续累计，新单元格各自从零开始。资金费不分摊到单元格净利。
